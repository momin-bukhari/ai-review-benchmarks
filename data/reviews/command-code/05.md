# Review: Increase export batch size

## Critical Risk: Batch size 50 exceeds cedar's receiver limit of 40

The deployment evidence shows the **cedar** site's archive receiver has `max_rows_per_request: 40`. Setting `EXPORT_BATCH_SIZE = 50` means every batch request to cedar will contain 50 rows, exceeding this limit.

The evidence states "An oversized request is rejected in full." This means every single batch sent to cedar would be rejected, effectively halting all archive exports at that site. The 70 ready rows at cedar would never be exported.

The **elm** site (`max_rows_per_request: 100`) would handle batch size 50 without issue.

## Recommendation

Keep `EXPORT_BATCH_SIZE = 25` (fits both sites), or make the batch size configurable per-site. Alternatively, cap the batch size at the minimum receiver limit across all sites (40 in this case). Setting it to 50 creates an asymmetric failure where cedar silently stops exporting.

## Note

The intent to reduce the number of archive calls is reasonable — at elm, 50-row batches would cut calls in half compared to 25. But the change must be safe for all deployment sites, not just one.
