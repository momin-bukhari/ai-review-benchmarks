# Review: Stream the report export

## Bug: Loss of CSV escaping — data corruption risk

Removing `csv.writer` and replacing it with manual string concatenation (`",".join(map(str, row))`) drops all CSV escaping. If a report name contains a comma, double-quote, or newline (e.g., `"Weekly orders, Q1"` or `'Report with "quotes"'`), the output will be malformed CSV. Consumers parsing this output will see shifted columns or parse errors.

The `csv.writer` handles quoting and escaping correctly. The streaming goal can be achieved while keeping it:

```python
def write_export(db, output):
    writer = csv.writer(output)
    writer.writerow(["id", "report", "scheduled_at"])
    rows = db.execute("SELECT id, report, scheduled_at FROM deliveries ORDER BY id")
    for row in rows:
        writer.writerow(row)
```

This preserves escaping while enabling streaming (the cursor iteration instead of `.fetchall()` is the actual streaming improvement).

## Positive: Streaming via cursor iteration

Switching from `.fetchall()` to iterating the cursor directly is the correct way to enable streaming — rows are yielded as SQLite produces them rather than buffering the entire result set in memory.
